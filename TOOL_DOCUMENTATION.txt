# CATS — Tool Documentation (REST League 2027)

## 1. Overview

**CATS** (Contract API Testing and Security) is an automated black-box OpenAPI testing and fuzzing tool for REST APIs
developed by Madalin Ilie. Given an OpenAPI (2.0, 3.0, or 3.1) specification in JSON or YAML format and a target base
URL, CATS automatically generates, correlates, and executes positive, negative, boundary, type-coercion, security
injection, stateful second-phase, and continuous multi-mutator fuzzing requests without requiring manual configuration.

- **Repository**: https://github.com/Endava/cats
- **RESTgym Tool Repository**: https://github.com/restgym/cats-tool
- **Documentation**: https://endava.github.io/cats/
- **License**: Apache-2.0

---

## 2. Requirements

- **Docker** (for running CATS inside the RESTgym competition harness), or
- **Java 25 JRE/JDK** (for running `cats.jar` directly on a host machine)
- **Maven 3.9+** (only if building `cats.jar` from source)
- **No GPU, no LLM, and no external internet access required** at runtime.

---

## 3. Installation

### Option A: Via the Official `restgym/cats-tool` Repository (Recommended for RESTgym Evaluation)

CATS is integrated directly into [RESTgym](https://github.com/restgym/restgym) as the `tools/cats` submodule
via [https://github.com/restgym/cats-tool](https://github.com/restgym/cats-tool), where the latest release (`cats.jar`,
`Dockerfile`, `entrypoint.sh`, and `restgym-tool-manifest.yaml`) is submitted via Pull Request.

From the root of a `restgym` checkout, update the `tools/cats` submodule (or place the submission files in
`tools/cats/`) and build the tool image:

```bash
git submodule update --init --remote tools/cats
./tools/build.sh cats
# or directly:
docker build -t restgym-tool-cats -f tools/cats/Dockerfile .
```

### Option B: Build `cats.jar` from Source

From the root of the [CATS source repository](https://github.com/Endava/cats):

```bash
./mvnw package -DskipTests -Dquarkus.package.jar.type=uber-jar
cp target/cats-runner.jar cats.jar
```

## 4. Running the Tool

### 4.1 Running in RESTgym (Docker Container)

The container expects the standard RESTgym environment variables:

| Environment Variable | Description                                                                                          | Required |
|----------------------|------------------------------------------------------------------------------------------------------|----------|
| `HOST`               | Hostname or IP address of the target API / proxy                                                     | Yes      |
| `PORT`               | TCP port of the target API / proxy                                                                   | Yes      |
| `API`                | API identifier (used to load `/specifications/${API}-openapi.json` or `/specifications/${API}.yaml`) | Yes      |
| `TIME_BUDGET`        | Testing time budget in minutes (e.g., `60`)                                                          | No       |

Run the container against a running RESTgym API container:

```bash
docker run --rm --network host \
  -e HOST=localhost \
  -e PORT=9090 \
  -e API=my-api \
  -e TIME_BUDGET=60 \
  restgym-tool-cats
```

When started, `/entrypoint.sh` executes a 4-stage testing loop until stopped by RESTgym at the end of the time budget:

1. **Stage 1a & 1b (Coverage & Resource Seeding Blitz)**: Pre-seeds collection `GET` endpoints, executes `HappyPath`,
   `OnlyRequiredFields`, `EmptyJsonBody`, `RemoveFields` (`--fieldsFuzzingStrategy SIZE --maxFieldsToRemove 2`), and
   `NumericValuesInStringFields` in dependency order with active runtime resource correlation (`RuntimeResourcePool`),
   followed by a schema/request-body example pass (`--useExamples`).
2. **Stage 2 (High-Yield Fault & Boundary Blitz)**: Runs 30+ boundary, type-coercion, control-character, Unicode
   case-expansion, auth-bypass, HTTP-method, and security injection fuzzers across all paths.
3. **Stage 3 (Full Black-Box Sweep)**: Runs all 160 first-phase fuzzers (including emoji, whitespace, control-character,
   and full security injection payloads) and all 7 stateful second-phase consistency fuzzers.
4. **Stage 4 (Seeded Continuous Random Mutation Fuzzing)**: Runs `RandomFuzzer` alongside `HappyPath` and
   `OnlyRequiredFields` with 25 body and header mutators (including multi-field stacked mutations, boundary numbers,
   type-confusion structures, and injection payloads) in an infinite `while true` loop until the container is terminated
   by the harness.

### 4.2 Running Standalone via `cats.jar`

To run CATS directly from the command line against any OpenAPI specification and server URL:

```bash
java -jar cats.jar \
  --contract /path/to/openapi.json \
  --server http://localhost:8080 \
  -b -k \
  --preseedCollectionGets \
  --includeEmojis \
  --includeControlChars \
  --includeWhitespaces \
  --includeAllInjectionPayloads
```
